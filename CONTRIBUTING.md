# Contributing

## Chapter standard

Each mature chapter should eventually contain:

1. Overview
2. Why this tool or approach
3. Installation
4. Configuration
5. Verification
6. Best practices
7. Alternatives
8. Troubleshooting
9. Common mistakes
10. Reference links

## Style

- Use GitHub Flavored Markdown.
- Use one H1 heading per file.
- Use fenced code blocks with a language identifier.
- Keep commands executable and platform-specific assumptions explicit.
- Prefer authoritative documentation for references.
- Mark unverified benchmarks and assumptions clearly.
